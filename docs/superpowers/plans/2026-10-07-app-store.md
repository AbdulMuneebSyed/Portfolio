# App Store Plan

**Goal:** Add an **App Store** app to MuneebOS that presents Syed Abdul Muneeb's
projects, work, skills and games the way the macOS App Store presents
software. A visitor can browse it, open a product page for each project,
read and leave ratings, and use **Get** to install extra apps into the Dock,
Finder and Spotlight.

**Why:** The Projects window lists the work. The App Store *sells* it: hero
stories, rankings, ratings and a "Get" button make each project read like
a shipped product, which is what a recruiter should take away.

**References:** the six macOS App Store screenshots (Discover, Discover
shelves, Things 3 product page, Work, Account, Play).

---

## 1. Concept: what is an "app" in this store?

Everything in the store is a `StoreItem`. There are four kinds:

| Kind | Examples | Primary button | What it does |
|---|---|---|---|
| `project` | AiResumate, GetMarks, LaunchPad, Capco-CS, E-Cell Hackathon | **View** ↗ (or **Open** for in-OS demos) | Opens the live site in Safari, or the in-OS app |
| `builtin` | About Me, Resume, Contact, Terminal, Finder | **Open** | `launchApp(id)` |
| `installable` | Snake, Minesweeper, Calculator, Notes, Music, plus new mini-apps | **Get** → progress ring → **Open** | Installs into the Dock, Finder › Applications, Spotlight, Terminal and the phone Home Screen |
| `experience` | Pulsegen, MathonGO, Capco-CS, E-Cell MJCET | **Open** | Opens About Me on the matching timeline entry |

The developer of every item is **Syed Abdul Muneeb**. The store sells
nothing, so there are no prices: buttons say Get, Open or View.
(The reference screenshots show ₹ prices, which would read as a real shop.)

## 3. Screens

### 3.1 Window shell
- New registry app `app-store`, title **App Store**, unified toolbar (default
  chrome in `components/window.tsx`), default size 1100 × 720, sidebar width
  ~230px using the existing `mac-sidebar` / `sidebar-item` classes.
- Toolbar: back chevron when there is history; the page title moves into the
  toolbar once the large title scrolls under it (screenshot 2); share button
  on product pages (copies a deep link).
- Internal router state: `{ tab, stack: Route[] }`, where
  `Route = { kind: "tab" | "product" | "seeAll" | "category" | "search", id?, query? }`.
  Back pops the stack; changing tab resets it.

### 3.2 Building blocks (reused by every tab)
- `HeroBanner` — eyebrow, title, subtitle, art or looping video, 16:5 aspect.
- `EditorialCard` — eyebrow/title/subtitle with round or full-bleed art (screenshot 1, row 2).
- `StoryCard` — tall artwork card with caption below (screenshot 6).
- `AppShelf` — titled 3-column grid of `AppRow`s, 3 rows, "See All" (screenshot 2).
- `AppRow` — icon, name, subtitle, `GetButton`, divider.
- `GetButton` — states `get → waiting → installing (progress ring) → open`, plus `view ↗`. Same component on rows and product pages.
- `CategoryTile`, `SectionHeader`.

### 3.3 Product page (screenshot 3)
1. Header: large icon, name, developer link, primary button, share.
2. Stats strip (scrolls horizontally on narrow widths):
   Ratings (count + average, from Supabase), Awards ("Editors' Choice" or a real award), Age rating "4+", Chart ("No. 1 in EdTech"), Developer, Language, Size (bundle size or "Web").
3. Screenshot carousel with snap scrolling and keyboard arrows; click opens Photo Preview.
4. Platform line: "Mac · iPhone · Web".
5. Description with **more**; side links: Developer, Website, Support (Contact).
6. Ratings & Reviews: big average, star histogram, 3 review cards, **Write a Review** (sheet → Supabase), See All.
7. What's New: version and date, notes, Version History (project milestones, e.g. "1L+ weekly rank updates").
8. Information grid: Seller, Category, Tech stack, Compatibility, Languages, Copyright, Links.
9. "More by Syed Abdul Muneeb" shelf, "You might also like" (same category).

### 3.4 Phone (< 700px)
Use iOS App Store layout instead of the sidebar: bottom tab bar
**Today · Games · Apps · Arcade · Search**, cards stacked full width,
product page with a sticky header button. Account opens from the avatar in
the top right.

## 4. Data model

```ts
// lib/app-store/catalog.ts
export type StoreKind = "project" | "builtin" | "installable" | "experience";

export interface StoreItem {
  id: string;                 // matches APP_REGISTRY id for builtin/installable
  kind: StoreKind;
  name: string;
  subtitle: string;
  icon: { appId: string } | { src: string };   // reuse AppIcon where possible
  category: StoreCategory;
  tabs: StoreTab[];           // which sidebar tabs list it
  description: string;
  highlights?: string[];
  techStack?: string[];
  links?: { website?: string; source?: string };
  screenshots?: string[];     // /app-store/<id>/1.webp …
  chart?: { rank: number; list: string };
  award?: string;
  sizeLabel?: string;
  versions: { version: string; date: string; notes: string }[];
  appearance?: { tint: string };  // hero/eyebrow colour
}

// lib/app-store/editorial.ts — per-tab layout, data only
export type Section =
  | { type: "hero"; itemId: string; eyebrow: string; title: string; subtitle: string; art: string }
  | { type: "cards"; cards: { itemId: string; eyebrow: string; title: string; subtitle: string; art: string }[] }
  | { type: "shelf"; title: string; itemIds: string[] }
  | { type: "stories"; stories: { itemId: string; eyebrow: string; title: string; subtitle: string; art: string }[] };
export const EDITORIAL: Record<StoreTab, Section[]>;
```

Single source of truth: the `projects` array now inside
`components/windows/projects-explorer.tsx` moves to `lib/projects.ts`, and both
Projects and the App Store read it. Experience data moves out of
`about-window.tsx` the same way.

### Install state
```ts
// lib/app-store/store.ts — zustand + persist, key "muneebos-app-store-v1"
interface AppStoreState {
  installed: string[];               // registry ids
  progress: Record<string, number>;  // 0–1 while installing, not persisted
  updatedTo?: string;                // last "MuneebOS" version the visitor updated to
  redeemed: string[];                // promo codes
  install(id: string): void;         // animates progress ~1.5s, then adds id, notifies
  uninstall(id: string): void;       // closes its windows, removes from Dock
  isInstalled(id: string): boolean;
}
```

Registry changes (`lib/types.ts`, `lib/app-registry.ts`):
- `AppRegistryEntry.installable?: boolean` and `preinstalled?: boolean`.
- Portfolio and system apps are always installed. Snake, Minesweeper and the
  new mini-apps start **not installed**; Calculator, Notes, Music start
  installed but can be removed.
- `getLaunchableApps()` filters out uninstalled apps, so Finder, Terminal
  `apps`, and Spotlight follow automatically. Spotlight shows uninstalled
  apps with a "Get in App Store" row instead of hiding them.
- Dock: installed apps can be kept in the Dock (`dockExtras` in the store).
- Phone Home Screen: Games folder lists only installed games.

## 6. Ratings and reviews

**Dropped (decision 3).** Product pages have no ratings, reviews or review
form, and the stats strip shows Category, Chart, Developer, Built with, Age
and Size instead. Supabase is not touched.

## 7. Assets

- `public/app-store/<id>/` — 2–4 screenshots per project (1280 × 800 WebP,
  < 150 KB each) and one hero/card artwork per editorial slot.
- Project icons: real logos where Muneeb owns them (AiResumate, LaunchPad);
  otherwise the existing glyph-tile style from `lib/app-icons.tsx`.
- Hero artwork: generated gradients/illustrations or own captures. Do **not**
  reuse Apple's editorial art or third-party app art from the reference
  screenshots.
- Hero video: short muted MP4/WebM screen recording of AiResumate, `preload="none"`,
  paused when Reduce Motion is on or the window is not visible.
- Lazy-load: the App Store window is `next/dynamic`-imported so the desktop's
  first load doesn't grow; images use `next/image` with `sizes`.

## 8. Implementation phases

`npm run build`, and a browser check at 1440 × 900 and 390 × 844.

## 9. Testing

- **Unit (scripts/test-macos.cjs):** catalog integrity, install/uninstall persistence, `getLaunchableApps` filtering, `findAppByAlias` ignores uninstalled apps, deep-link route parsing, promo-code redemption.
- **Type and build:** `tsc --noEmit`, `next build`.

## 10. Decisions (confirmed 2026-10-07)
